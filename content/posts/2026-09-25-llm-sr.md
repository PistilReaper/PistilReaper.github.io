# [LLM-SR: Scientific Equation Discovery via Programming with Large Language Models](https://openreview.net/pdf?id=m2nmp8P5in)

符号回归需要同时确定表达式结构和数值系数。系数可以交给数值优化器，但下一步应该尝试什么结构，往往很难决定。如果已知数据来自一个振子，驱动、阻尼和恢复力就会成为自然的起点；如果已知研究对象是细菌生长，资源限制、温度和 pH 的影响也会进入考虑。这些知识还不足以确定方程，却能改变不同结构被优先尝试的机会。

本文将与大家讨论 Parshin Shojaee 等人的 *LLM-SR: Scientific Equation Discovery via Programming with Large Language Models*，发表为 ICLR 2025 Oral。

LLM-SR 试图把这件事变成一个可运行的搜索过程：**用 LLM 的科学知识提出方程结构，用数值优化拟合系数，再让数据评价影响下一轮生成。**它的核心问题是，已有知识能否帮助搜索更快地进入有希望的结构区域，以及这种帮助在什么条件下成立。

## 01 相关工作

遗传编程通过变异、交叉等操作产生新表达式；[Deep Symbolic Regression（DSR）](https://arxiv.org/abs/1912.04871)用神经网络逐步生成符号序列，再根据拟合奖励更新生成策略。两者都在调整搜索对不同表达式的偏好，只是实现方式不同。

[NeSymReS](https://proceedings.mlr.press/v139/biggio21a.html)进一步把一部分工作移到预训练阶段：先从大量合成的“数据—表达式”配对中学习，再根据新数据生成方程骨架、拟合常数。到这里，神经网络参与结构生成已经有了明确的方法基础。那么，考虑到 LLM 的强通用性和极其丰富的跨领域知识，使用通用 LLM 是否能将从数学、代码和科学文本中学到的潜在知识接入到候选表达式生成中呢？

使用 LLM 生成候选表达式这条路线有直接的前置工作。2023 年公开的 [Language Model Crossover（LMX）](https://arxiv.org/abs/2302.12170)将已有表达式作为示例，让语言模型生成新表达式，并在符号回归上进行了实验；Google Deepmind 的 [FunSearch](https://www.nature.com/articles/s41586-023-06924-6) 则把程序生成、外部评价和优质候选复用组织成了迭代搜索框架。与 LLM-SR 几乎同期公开的 [ICSR](https://aclanthology.org/2024.acl-srw.49/)，同样采用 LLM 改进函数形式、外部优化器拟合系数的分工。

因此，评价 LLM-SR 的贡献，需要具体到科学背景、程序表示和搜索反馈怎样配合。但不可否认的是，大家目前往往会将 LLM-SR 这个工作作为将 LLM 引入为符号回归的候选生成器的早期代表性工作。LLM-SR 的学术影响力和方法完整度明显高于早期的 LMX SR experiment，而且 ICLR Oral 给它带来了更大的可见度（相较于 [ICSR](https://aclanthology.org/2024.acl-srw.49/) 的 ACL 2024 **Student Research Workshop**）。

科学先验本身也早已进入 SR。例如，[DHC-GEP](https://arxiv.org/pdf/2211.09679) 和 [PhySO](https://arxiv.org/abs/2303.03192) 都把量纲约束直接放进表达式生成过程。LLM-SR 提供的是一种更灵活的知识输入方式：自然语言可以描述变量含义、机制背景和任务要求。相应地，这些信息对生成过程的影响也更难精确控制。量纲检查可以明确判定某个构造是否合法，自然语言背景则主要改变模型倾向于提出什么。这个争议点我们也会在最后一部分进行讨论。

## 02 把结构与系数分开

我们先沿着一个候选走一遍，看看 LLM-SR 的一轮搜索是如何进行的。

假设任务是根据输入时间 $t$、位移 $x$ 和速度 $v$，寻找振子的加速度关系。LLM 可以提出下面这样一个程序。这里只用它解释方法，并非复现论文某一轮的原始输出：

```python
import numpy as np


def equation(t, x, v, params):
    a, w, c, d, k = params
    driving = a * np.sin(w * t)
    damping = -c * v**3
    restoring = -d * x * np.exp(k * x)
    return driving + damping + restoring
```

对应的数学表达式是

$$
f(t,x,v;\theta)
=a\sin(\omega t)-cv^3-dx\exp(kx).
$$

这个候选已经作出了几个结构选择：驱动项用正弦，阻尼项用速度的三次方，恢复力项包含位移与指数函数的乘积。但 $a,\omega,c,d,k$ 这些参数取多少，还没有确定。

如果直接拿一组随手生成的系数去打分，会发生什么？即使结构接近真式，只要驱动频率或阻尼系数偏得太远，拟合误差也可能很大。这个分数混合了结构和系数两方面的影响，过早淘汰候选就可能错过一个好结构。

LLM-SR 因此把两件事拆开：LLM 提出函数形式，数值优化器先把其中的系数拟合一遍，再评价这个候选。

注意，将符号结构搜索与数值系数估计分工处理，在早期符号回归研究中已有明确实践。Iba 等人的 STROGANOFF 系列工作于 1993—1994 年结合了遗传算法结构搜索与回归定参；Topchy 与 Punch 在 2001 年进一步研究了程序树进化与数值叶节点梯度优化的结合。

科学知识主要在生成结构时发挥作用。prompt 会告诉模型哪些变量是时间、位移和速度，目标是加速度；同时提供任务说明、评价与参数优化代码，以及历史候选程序。这样，模型有机会从驱动、阻尼、恢复力等机制出发组织表达式。整份观测数据不会被完整写进提示，数值数据通过外部评价影响后续搜索。

*图 2｜LLM-SR 的提示示例（[图片来源](https://arxiv.org/html/2404.18400v3/fig_table_file/fig2_prompt_v10.jpg)）。*

把这个过程写成公式，设 $s$ 表示结构，$\theta$ 表示系数，$c$ 表示科学背景，$\mathcal H_t$ 表示当前搜索经验，则一轮生成和拟合可以概括为

$$
s_t\sim p_\phi(s\mid c,\mathcal H_t),
$$

$$
\hat\theta_{s_t}\approx
\arg\min_\theta
\frac1N\sum_{i=1}^N
\left[y_i-f_{s_t}(\mathbf x_i;\theta)\right]^2.
$$

第一行决定尝试什么结构，第二行决定这个结构的系数取多少。$\phi$ 是 LLM 的参数，搜索中始终固定；变化的是候选、提示和每个候选内部的 $\theta$。所以这里的迭代属于推理时搜索，无须每轮重新训练语言模型。

我们可以想象，对于完全相同的算子集合，在不同的科学背景 $c$ 下，可以得到很不一样的候选分布。“这是位移和速度”这样的描述，可能提高某些力学结构被生成的概率。这个分布是否有用，要由第二行之后的数据评价检验。

论文使用 NumPy+BFGS 或 PyTorch+Adam 拟合系数，以拟合后的负 MSE 作为主要评分；无法执行或超过资源限制的程序被丢弃。这里写 $\approx\arg\min$，是因为数值优化不保证找到全局最优。一个候选的分数差，既可能是结构不合适，也可能是参数没有拟合好。

得到分数之后，还需要让下一轮用上这次尝试。LLM-SR 采用多岛候选池，这个做法类似于 PySR，不同岛保留各自的搜索轨迹。采样机制优先考虑分数较好的候选，并偏好较短程序；表现较差的岛会被周期性重置。作者表示这部分参考了 FunSearch 的设计。回到振子的例子，已有候选可以作为下一轮示例，让模型继续修改其中某个项，或者重新组合不同的机制。

LLM-SR 让方程“更简洁”的机制与很多传统 SR 方法的做法不同，并没有显式优化

$$
\text{loss}+\lambda\cdot \text{complexity}
$$

 这种 Pareto / complexity-penalty 目标。它主要依赖三个间接机制。

**第一，在 experience buffer 采样时偏向更短的程序。**LLM-SR 会先从某个 island 中选择较高分的 candidate cluster，然后在该 cluster 内部采样具体程序时，对短程序赋予更高概率。论文写成：

$$
P(f_i)\propto \exp\left(-\tilde l_i/\tau_p\right)
$$

，其中 $l_i$ 是程序长度，实际用的是代码字符数来度量长度。被抽中的短程序会作为 in-context examples 放进下一轮 prompt，因此 LLM 会更频繁地看到“短且拟合较好”的程序，间接诱导后续生成也保持简洁。

第二，**限制参数数量**。所有实验中作者都把 `params` 向量的最大长度限制为 10，主要目的是防止过度参数化和过长的候选方程。

**第三，LLM 本身会根据高分历史程序做结构改写。**experience buffer 中高分候选不断返回 prompt，LLM 在这些结构基础上修改、合并或删除项，因此有机会自然地产生更紧凑的表示。不过这一点依赖 LLM 的生成偏好，没有严格的 complexity objective。

至于为什么用程序，前面的例子已经给出了很直接的理由：驱动、阻尼和恢复力可以分别写成中间量，数值库和优化器也能直接接入。程序表示因此很适合衔接 LLM 的代码能力（特别是现在，基模本身的 coding 能力感觉有质的飞跃）。

## 03 实验与结果

实验部分最需要检查的是：额外给出的科学背景，是否真正给出了更有方向的搜索。

把数据记为 $\mathcal D$，这个任务设置可以写成

$$
\mathcal D\longrightarrow f
\qquad\Rightarrow\qquad
(\mathcal D,c)\longrightarrow f.
$$

多出来的 $c$ 包含变量含义、问题背景和任务约束。因此，除了最终误差，还要看这些信息是否改变了搜索过程，以及收益能否延续到观测范围之外。

作者引入了细菌生长任务这个 case。生长率由细菌数量、底物、温度和 pH 等因素共同决定。如果能先提出“几个机制因子的乘积”，搜索就有了一个可以逐项修改的起点。论文展示的轨迹中，LLM 较早提出了温度和 pH 存在最适区间的结构，随后继续调整具体的非线性形式。收益可能来自这样的机制分解，也可能来自较好的初始候选。

但这个例子马上带来另一个问题：模型是在根据数据修改假设，还是回忆出了训练时见过的公式？

作者为此设计了四个测试问题：两个修改过的非线性振子、一个包含自定义非线性关系的细菌生长模型，以及真实铝合金拉伸数据。这些任务保留科学背景，同时加入需要由数据辨别的关系，尝试降低直接复述经典公式的可能性。

论文还比较了这些任务与 Feynman 任务的困惑度和搜索误差轨迹，用于诊断记忆风险。当然，这些检查有参考价值，但不能严格排除训练数据污染。

消融实验的结论其实也不能完全区分模型本身没有先验的表现。`w/o Prior` 删除的是问题和变量的自然语言描述，模型参数中已有的知识仍然保留。这个对照支持“显式科学语义有帮助”，并没有回答“模型完全缺少相关知识时会怎样”。

## 04 知识与计算的代价

作者在结论中明确承认两类限制。

一类来自预训练知识。某个领域在训练数据中覆盖不足，或者模型学到的经验存在偏差，都会影响候选生成。这个限制与前面的收益来自同一机制：知识提高了一些结构的生成概率，也可能让搜索反复停留在不合适的结构附近。

另一类来自计算成本。每轮调用 LLM，还要为候选进行参数优化；问题规模增大后，这部分开销可能难以承受。达到相近误差所需的候选较少，可以说明搜索更有效，但不能直接换算成总耗时更低。一次 LLM 生成与一次简单符号变异的成本并不相同。

作者提出的后续方向包括领域语言模型、检索增强、领域专家参与，以及更全面、能够降低公式复述风险的评测基准。这些都是围绕知识质量和评价环境展开的改进方向。

更进一步的问题是：当目标变成未知方程发现，预测误差之外还需要什么？下面的讨论属于在原论文基础上的延伸。

在 Oscillation 2 case 中，真值方程的恢复力项是

$$
g(x)=-5xe^{x/2},
$$

而作者展示的 GPT-3.5 搜索结果使用了

$$
\hat g(x)=5(1-e^x).
$$

其他几个主要项被恢复出来，但这两个恢复力项显然不是同一个函数。为什么不同的结构仍然可能给出接近的数值结果？论文附录讨论了它们在观测范围内的近似关系；在 $x=0$ 附近做一个展开，可以更直接地看到原因：

$$
\begin{aligned}
g(x)&=-5x-\frac52x^2-\frac58x^3+O(x^4),\\
\hat g(x)&=-5x-\frac52x^2-\frac56x^3+O(x^4).
\end{aligned}
$$

前两阶完全相同，差异从三阶开始。如果采样条件不足以分辨这部分差异，两种结构就可能得到接近的误差。当然，这个局部展开本身并不给出整个观测区间的误差保证。

因此，预测误差和结构恢复是两个需要分别检查的指标。一个简单、泛化良好的近似式有实际价值；若目标是恢复合成数据的真式，还要检查符号结构。真实实验往往没有已知 ground truth，此时能做的检验包括跨条件稳定性、表达式复杂度和物理一致性。

在符号回归的评价环节同样可以扩展。除了拟合误差，还可以检查不同工况上的预测、规范化表达式的复杂度，以及结构在重采样下是否稳定。复杂度应在约定的符号表示上计算：变量名、代码格式和中间量写法都能改变程序长度，却未必改变方程本身。删除一个系数很小的项，也应结合噪声水平与参数不确定性判断，避免把较弱的真实机制一并删掉。

最后，当两个不同结构都能解释现有数据，单纯增加同一批数据上的搜索次数未必能解决问题。更有价值的下一步，可能是寻找让它们给出不同预测的初始条件、激励或采样区域，再通过模拟或实验取得新证据。LLM 可以参与提出方案，候选之间的区分度和实验可行性则交给外部工具评价。

这会把流程延伸到主动获取证据，但原论文尚未完成这样的实验闭环。验证这一方向时，可以针对不同于常见模型的机制结构构造测试任务，对同一份数据分别提供匿名变量、正确背景和误导背景，并在相近计算预算下同时检查预测误差与符号恢复率。这些对照有助于判断，收益究竟来自可迁移的结构推断，还是依赖背景恰好指向了正确答案。
